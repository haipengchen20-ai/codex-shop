# 多平台商城链接图片采集设计

## 目标

将现有 Steam 图片收藏器扩展为可从公开的 Nintendo Switch、PlayStation Store（PS4/PS5）和 Xbox 商城链接采集游戏图片；保留 Steam 现有功能与每日表格同步。

## 选定方案

采用“商城链接直采”：用户提供官方商品页链接，程序从链接识别平台并解析该页面公开提供的封面与截图。不会使用第三方游戏数据库，也不要求 API 密钥。

## 输入与平台识别

- 网页输入框接受 Steam AppID/链接或官方商城链接。
- Excel 表格继续使用“游戏名字”和“游戏链接”两列；B 列可混合四个平台的链接。
- 通过域名自动识别平台：Steam、Nintendo、PlayStation Store、Xbox/Microsoft Store。
- 无法识别的链接在网页中直接提示；批量同步将该游戏记录为失败，但继续处理后续行。

## 图片采集与保存

- Steam：保持现有规则——封面、前 4 张截图、系统需求图。
- Switch、PlayStation、Xbox：保存商城公开封面和最多 4 张截图；主机游戏没有“系统需求图”。
- 只保存源商城页面与其公开图片 CDN 所引用的图片，不从第三方图库补图。
- 每个平台的下载器设置官方允许的图片域名白名单；重定向后也重新校验。
- 同步结果记录平台、游戏名、实际保存数量、缺少的素材和错误原因；能保存封面但商城未公开截图时，任务视为成功并明确说明截图数量为 0。

## 界面与自动任务

- 标题、提示文案和输入占位符从“Steam”改为“多平台游戏图片收藏器”。
- 查询结果显示平台标签；图片项可照现有方式勾选、立即保存、定时保存。
- 自动任务的唯一标识改为“平台 + 商品链接/商品 ID”，避免不同平台同号冲突。
- 当前 Codex 每周一至周六 11:00 的同步继续使用同一份 Excel 表，只需添加主机商城链接。

## 容错与验证

- 对商城中仅由客户端脚本生成且无法从公开页面数据取得的素材，报告“商城未公开可下载图片”，而不伪造成功。
- 以每个平台至少一个真实官方链接进行验证；检查封面、截图数量、保存位置和表格混合同步。
- 新增解析器、平台识别、域名校验、任务键和混合表格同步的自动测试；现有 Steam 测试必须全部通过。

## 不在本次范围

- 不采集需登录、付费或私有素材。
- 不从 IGDB、搜索引擎或第三方游戏资料站补图。
- 不生成主机游戏的系统需求图。
